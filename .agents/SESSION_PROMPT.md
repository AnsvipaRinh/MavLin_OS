# Стартовый промпт для внешних агентов (Grok, GPT, Perplexity)

Вставь блок между линиями в начало сессии или напиши агенту одну строку из конца файла.
Протокол целиком: `docs/COORDINATION.md`. Формат заявок: `.agents/README.md`.

---
Работаешь в репозитории AnsvipaRinh/MavLinOS вместе с другими агентами. Перед любой правкой:

1. Прочитай `docs/COORDINATION.md` (одна страница) и посмотри `.agents/claims/`.
2. Не начинай, если твои пути входят в чужой активный claim или уже делаются в открытом PR или ветке `wip/*`, `work/*`.
3. Создай свой claim-файл (формат в `.agents/README.md`, одна запись меньше 1 КБ). В каждом коммите пиши строку `Claim: <id>`, а не свободный текст.
4. В `main` попадает только цельное и рабочее. Если для задачи нужно больше одной записи, работай в ветке `wip/<твоё-имя>-<тема>` и вливай одним PR или merge.
5. У тебя есть лимит на размер записи (например около 1,4 КБ): не режь большие файлы на части и не перезаписывай их целиком. Положи готовый файл в ветку `wip/...` и напиши в issue #1 одной строкой, что готово.
6. Тест без `assert`/`check` тестом не считается. Не запускай `bin/mv-*` из тестов без изоляции `scripts/gui-guard` (`mv_gui_iso`).
7. Закончил: удали свой claim-файл.

Защищённые файлы (`.agents/protected.txt`): `AGENTS.md`, `opencode.jsonc`, `.opencode/*`, workflows, `scripts/check-sync.sh`, реестр хоткеев и сгенерированный из него XML. Меняй их только под активным claim.
---

## Если коротко

Одной строкой агенту: **«Прочитай `docs/COORDINATION.md` и `.agents/README.md` в репозитории и следуй им, затем начинай работу.»**

## Заметки для конкретных агентов

- **Grok.** Многочастная заливка файла в `main` запрещена (правила R2, R3). Если файл больше твоего лимита записи, положи его в ветку `wip/grok-<тема>` и напиши в issue #1. Сборку цельного файла сделает opencode: у него есть shell и тесты.
- **GPT.** Перед открытием PR проверь `.agents/claims/` и открытые PR на пересечение путей. В описание PR добавь необязательную секцию `### Coordination` из шаблона (`Claim: <id>`).
- **Perplexity.** Не добавляй тесты ради «покрытия»: каждый тест обязан что-то проверять (`assert`) и не запускать настоящее GUI-приложение. Если есть shell, запусти `python3 tools/lint-tests.py` перед коммитом.
- **Claude.** Работает только по просьбе владельца; правки через ветку или прямую запись с `Claim:` в коммите.
