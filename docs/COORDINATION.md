# Координация нескольких агентов

Действует с 2026-10-06. Черновик: Claude по просьбе владельца репозитория.
Обязательно для **всех**, кто пишет в репозиторий: opencode (Orchestrator/Build), Grok, GPT, Claude, человек.

**Суть в одной строке:** заяви работу (claim) → делай маленькую законченную правку → в `main` попадает только полное и рабочее → сними claim.

- **`thunarrc`.** Grok восстановил файл (09:31), opencode в 09:38 сознательно удалил его как мёртвый конфиг, в 09:41 удалил снова после rebase.
- **`mv-empty-trash`.** Написали и Grok (09:59), и opencode (10:17). Версия opencode потерялась при rebase и была восстановлена вручную (10:22).
- **Общий worktree opencode.** Массовый rewind (~04:46), `git stash` одного агента смёл чужие правки, файлы терялись при rebase, правки одной сессии попадали в коммит другой.
- **Красный CI.** `main` был красным 30+ коммитов подряд (72 из 80 прогонов), сигнал перестал что-либо значить.

## 2. Кто как пишет

| Агент | Как пишет | Типичная опасность |
|---|---|---|
| opencode (Orchestrator + Build-воркеры) | коммиты прямо в `main` из локального worktree | общий worktree у параллельных воркеров, stash/rewind/rebase |
| Grok | запись через API, лимит ~1.4 КБ на запись | обрезанные и многочастные записи большого файла прямо в `main` |

## 3. Правила

**R1. Claim.** Перед правкой посмотри `.agents/claims/`, открытые PR и ветки `wip/*`, `work/*`. Если твои пути пересекаются с активным claim другого — не начинай, возьми другой объект. Иначе создай claim (формат в `.agents/README.md`) и пиши в коммитах `Claim: <id>`. TTL не более 6 часов; истёк — путь свободен; закончил — удали файл. Комментарий в issue #1 допустим как дубль, но файл первичен: его видят все и его проверяет CI.

**R2. В `main` только полное и рабочее.** Любая доставка из нескольких записей (многочастная, из нескольких коммитов, зависящая от другой записи) идёт в ветку `wip/<agent>-<slug>` и вливается **одним** merge/PR. Запрещены промежуточные состояния в `main`: `PLACEHOLDER`, «loader + parts», «убрал из XML, пока нет в ACTIONS».

**R3. Лимит инструмента.** Агент с ограниченной записью (Grok) не переписывает крупные файлы целиком и не режет их на куски. Либо доставляет точечный патч в рамках лимита (в ветку), либо оставляет изменение целиком в issue/PR для владельца или opencode. После записи проверь размер и `py_compile`.

**R4. Защищённые файлы** (`.agents/protected.txt`): реестр хоткеев и генерируемый из него XML, `AGENTS.md`, `opencode.jsonc`, `.opencode/*`, workflows, `scripts/check-sync.sh`. Меняются только под активным claim. XML регенерируется из реестра, руками не правится.

**R5. Рабочая копия (opencode).** Каждый параллельный воркер получает свой worktree: `git worktree add ../mavlinos-wt/<oid> -b work/<oid> origin/main`. Один worktree — один воркер. В любой общей копии запрещены: `git stash`, `git reset --hard`, `git checkout -- .`, `git restore .`, `git clean -fd`, force-push, rebase чужих коммитов. Откат — `git revert`, потерянное — через `git reflog`.

**R6. Дедупликация.** До старта: строка в `docs/APPS.md`, `git log -S<имя>`, открытые PR и ветки, claims. Уже делается другим — допиши в его ветку/PR или выбери другое.

**R7. Зелёный `main`.** Перед push: `scripts/check-sync.sh` для затронутой зоны. Если `main` красный не по твоей вине — не добавляй нового красного и отметь это в claim или issue. Красный 3 коммита подряд = остановить feature-работу и чинить.

**R8. Документы.** `APPS`, `PROGRESS`, `DECISIONS`, `NEEDS_HARDWARE_TEST` только дописываются в конец, в том же коммите, что и код. Перед правкой `git pull --rebase`. При конфликте сохраняй обе стороны.

**R9. Чужую работу не перетирают молча.** Удаление или откат чужого — только с записью в `docs/DECISIONS.md` (причина) и под claim.

## 4. Минимум для агента без shell (Grok, GPT-чат)

1. Прочитай `docs/COORDINATION.md` и `ls .agents/claims/`.
2. Создай файл claim (одна запись, меньше 1 КБ).
3. Работай в ветке `wip/<agent>-<slug>`; в `main` — только законченное (R2).
4. В коммитах и PR: `Claim: <id>`.
5. Закончил: удали claim, закрой PR или влей.

## 5. Что проверяет CI (`Agent Guard`)

Workflow `.github/workflows/agent-guard.yml` на каждый push в `main` и каждый PR:
- **падает**, если изменённый файл ≤64 байт и состоит только из `PLACEHOLDER`;
- **предупреждает**, если правка попала в путь чужого активного claim без ссылки на него;
- **предупреждает** о правках защищённых файлов и об `_core_part_*` (обходной многочастный loader);
- на PR оставляет один обновляемый комментарий, в остальных случаях пишет в Step Summary.

Это сигнал, а не запрет: ветку `main` он не защищает. Для жёсткой защиты владельцу нужно включить Branch protection (Settings → Branches).
