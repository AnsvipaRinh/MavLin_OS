## How the demo is produced

`scripts/demo/run-demo.sh` (committed in this tree) is fully reproducible:

1. Arms the project GUI isolation (`scripts/gui-isolation.sh`): the ambient
   host display (WSLg `:0` / `wayland-0`) is captured as FORBIDDEN and a
   fail-loud guard aborts any child that tries it (`HOST-DISPLAY-BLOCKED`).
   The demo runs on a dedicated Xvfb `:98` (1680x1050x24) — the user's real
   desktop is never touched (verified: 0 demo windows on the host display).
2. Stages the theme, panel plugin, rofi themes and `mv-*` apps from
   `git archive HEAD` of THIS repository into a throwaway prefix, so a
   concurrent dirty checkout can never alter a demo run.
3. Generates a disposable demo `$HOME` (`scripts/demo/make-demo-home.sh`)
   from the ISO skel (the real session config) plus documented demo
   overrides (96 DPI for the demo display, panel on top, demo files,
   demo Notes content).
4. Starts the real session stack: xfconfd → xfsettingsd → xfwm4 (Mavericks
   decorations, traffic lights left) → feh wallpaper (see limitations) →
   xfce4-panel (mv-apple plugin built from this repo) → plank (Mavericks
   dock theme + product pins).
5. Opens the real applications, arranges them deterministically (window
   matching by PID) and captures the Xvfb root window to PNG
   (`scripts/demo/demo-capture.py`).

Captured environment: Xvfb 1680x1050x24 (16:10), 96 DPI, Xfce 4.20 /
plank 0.11.89 / rofi 2.0 / GTK 3.24, Arch Linux container. Fonts: the
product stack asks for San Francisco / Lucida Grande, which are not
redistributable and are not installed here — fontconfig substitutes
Nimbus Sans (metric-compatible Helvetica clone) in these shots.

## Temporary demo data used

* `~/Documents`, `~/Projects` with deterministic demo documents
  (generated by `make-demo-home.sh`);
* demo Notes content (`~/.local/share/mv-notes/notes.json`);
* the wallpaper is the theme's own `mavericks-desktop.png`.

Nothing outside the throwaway prefix/demo HOME is modified at runtime.

## Product bugs found and fixed by this demo pass

All fixed on `main` (see the referenced commits):

1. `mv-apple.desktop` used `[Desktop Entry]` — xfce4-panel ≥ 4.19 only
   accepts `[Xfce Panel]`; the Apple-menu plugin could never load.
2. plank `dock.theme` was web-CSS (`rgba()`, inline comments) — plank
   silently ignored it and rendered the Default dock. Rewritten in valid
   plank format with the same Poppy-derived values.
3. All three rofi themes (`rofi-launchpad`, `rofi-mavericks`,
   `rofi-mission-control`) were web CSS / carried a rofi-2.0-invalid
   property — rofi aborted the modes with a parse-error dialog.
   Converted to valid rasi (validated with `rofi -dump-theme`).
4. `mv-textedit` passed the file argument through `GApplication.run`
   without `HANDLES_OPEN` — opening a document aborted the app. Same for
   `mv-finder-columns` with a folder argument.
5. `mv-textedit` used the GtkSourceView-3-only
   `begin_notifiable_actions()` API — every load_file aborted on
   GtkSourceView 4 (and a rewrite had also regressed the f643a2d ruler
   guard; re-applied).
6. `mv-mc-gui` crashed with `AttributeError: 'NoneType' object has no
   attribute 'wid'` whenever any thumbnail capture failed, and rendered
   one stretched thumbnail per row (FlowBox had no max-children-per-line).
7. Theme: treeview/iconview text had no explicit color in the stylesheet
   GTK 3.24 actually loads (`gtk-3.20/`), so Finder rows/labels rendered
   illegibly light-on-light; the whole view also wore a blue focus ring.
   Fixed in both the 3.0 and 3.20 layers.
8. `XFCE_PANEL_PLUGIN_REGISTER (construct);` (stray space, cd00b59)
   failed the `test-global-menu` contract.

## Known limitations of this demo (honest list)

* **Wallpaper**: xfdesktop 4.20.2 ignores its `/backdrop` xfconf
  properties in this headless Xvfb environment (every property-path
  layout was tried), so the harness sets the root wallpaper with `feh`
  and skips xfdesktop (no Home/Trash desktop icons in the shots).
  Needs one verification on real hardware; tracked in
  `docs/NEEDS_HARDWARE_TEST.md`.
* **Global app menu** (vala-panel-appmenu) is not in the shots: it needs
  vala/meson to build, unavailable in this container. The Apple menu
  (mv-apple) is present.
* **rofi 2.0 vs the product hotkey commands**: the skel still binds
  Spotlight/Launchpad to `rofi -show -modi …`, which rofi 2.0 rejects
  ("Mode -modi is not found"). The demo invokes rofi with the 2.0 syntax
  (`-modes … -show …`); the product keybindings need the same one-line
  migration (tracked for follow-up; the files are under active work by
  another session).
* **Launchpad icons** do not resolve in the demo container (icon-theme
  fallback chain); the grid renders text-only here.
* **Mission Control** is shown as an honest work-in-progress: the
  dedicated overlay runs and captures real thumbnails, but layout/polish
  is mid-flight upstream (issue #1 O-series).
* **Spotlight** (`05b` in earlier runs) is not part of the final set: as
  a rofi script mode it cannot render an empty-query result list (it
  exits with a usage error on the initial call), so the surface looks
  broken without a query — product-side follow-up.

## Reproducibility / verification

* The harness ran end-to-end repeatedly (≥6 clean runs) with identical
  setup steps; every PNG in this directory is a capture of a live
  session on `:98`.
* PNGs verified valid and non-empty (PIL verify, 1680x1050).
* Host display sampled during runs: 0 demo windows ever appeared on the
  WSLg desktop; the fail-loud guard was armed for the whole run.
* Relevant suites re-run after the product fixes: theme CSS (9/9),
  apple-menu packaging, global-menu contract, dock launchers,
  Launchpad id/migration suites, Finder search, TextEdit suite,
  F3 binding — all green. Two remaining failures are pre-existing at
  HEAD and belong to another session's in-flight work
  (`test-mv-finder-columns` — the concurrent rewrite removed the
  `build_columns_classes` factory the suite asserts;
  `test-mv-mission-control.test_native_backend_primes_workspaces_then_exposes`
  — needs a live WM for the native-expose path).
